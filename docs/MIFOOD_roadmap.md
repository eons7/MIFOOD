# Дорожная карта МИФУД

Минимально жизнеспособный продукт реализован и закрывает базовый сценарий предзаказа в столовой. Дальнейшее развитие разделено на три фазы: стабилизация, монетизация, полное покрытие точек питания МИФИ.

---

## Принципы планирования

1. Каждая фаза имеет критерий перехода к следующей.
2. Технический долг закрывается до начала новых функциональных задач.
3. Функции добавляются после подтверждения спроса, а не «на всякий случай».
4. Каждое изменение сформулировано как гипотеза с измеримой метрикой результата.

---

## Фаза 0. Текущее состояние

### Реализованный функционал

- Регистрация и авторизация пользователей.
- Каталог меню с категориями, поиском и группировкой позиций по размерам.
- Корзина с лимитом на количество позиций и активных заказов.
- Оформление заказа с выбором времени получения.
- Бронирование столов с настраиваемой длительностью от 5 до 45 минут.
- Доска заказов KDS для кухонного персонала с обновлением в реальном времени.
- Управление меню, столами и заказами в административной панели.
- Продление брони администратором с проверкой коллизий.
- Автоматический перевод неполученных заказов в статус «не забран».
- Уведомления о смене статуса заказа в реальном времени.
- Онлайн-оплата через ЮKassa в тестовом режиме.
- PWA: установка на устройство, offline-страница, кэширование статики.

### Реализованные технические характеристики

- Самохостинг внешних библиотек, исключающий зависимость от CDN.
- HTTPS с автоматическим сертификатом Let's Encrypt.
- 13 заголовков безопасности, включая Content-Security-Policy без `unsafe-inline`.
- Ограничение частоты запросов на 9 ключевых маршрутах.
- 58 автоматических тестов: безопасность, жизненный цикл сущностей, базовые сценарии.
- Аудит-логирование критичных действий администратора.
- Автоматическое развёртывание из main-ветки в Timeweb Cloud.

### Известные ограничения

- ЮKassa работает в тестовом режиме без реальных платежей.
- Возвраты средств не автоматизированы и выполняются вручную в кабинете ЮKassa.
- Flask-Limiter использует in-memory storage и сбрасывает счётчики при перезапуске контейнера.
- Резервное копирование PostgreSQL отключено.

### Критерий перехода к фазе 1

- Все запланированные пользовательские истории US-01..US-15 закрыты.
- Проведён пилотный запуск с участием не менее 10 студентов в течение недели.

## Фаза 1. Стабилизация

Цель — доведение MVP до уровня production-quality. Новый функционал не добавляется, фокус на снижении технического долга.

### Задачи

| #   | Задача                                                  | Назначение                                       |
|-----|---------------------------------------------------------|--------------------------------------------------|
| 1.1 | Покрытие тестами не менее 70%                           | Защита от регрессий при рефакторингах            |
| 1.2 | Подключение мониторинга на базе Sentry или аналога      | Раннее обнаружение сбоев                         |
| 1.3 | Перенос Flask-Limiter на Redis                          | Сохранение лимитов при перезапуске               |
| 1.4 | Включение резервного копирования PostgreSQL             | Защита данных                                    |
| 1.5 | Реализация автоматического возврата средств             | Устранение ручной операции у администратора      |
| 1.6 | Push-уведомления через Web Push API                     | Доставка уведомлений при закрытом приложении     |
| 1.7 | Алерты на повышенную частоту неуспешных входов          | Раннее выявление brute-force                     |
| 1.8 | Замена дефолтных паролей в seed-данных                  | Закрытие публично известной уязвимости           |

### Критерий перехода к фазе 2

- Покрытие тестами не ниже 70%.
- Отсутствие открытых дефектов уровня P0 и P1.
- Аптайм за календарный месяц не ниже 99,5%.
- Возвраты средств выполняются автоматически.

## Фаза 2. Монетизация и интеграции

Цель — получение первой выручки и интеграция с информационной инфраструктурой МИФИ.

### Задачи

| #   | Задача                                       | Гипотеза                                | Метрика                  |
|-----|----------------------------------------------|-----------------------------------------|--------------------------|
| 2.1 | Подключение боевого ЮKassa                   | Студенты готовы к онлайн-оплате         | Не менее 50% онлайн-оплат |
| 2.2 | Интеграция со СКУД МИФИ                      | Снимет барьер регистрации               | Рост регистраций на 30%  |
| 2.3 | Подписка «комбо обедов» со скидкой           | Готовность платить вперёд за скидку     | Не менее 100 подписок в месяц |
| 2.4 | Программа лояльности                         | Рост частоты заказов                    | Рост повторных заказов на 20% |
| 2.5 | Промокоды для маркетинговых кампаний         | Возможность измерения эффективности     | Сбор данных по конверсии |
| 2.6 | Поддержка 54-ФЗ через онлайн-кассу ЮKassa    | Юридическое требование при работе с деньгами | Соответствие закону  |

### Критерий перехода к фазе 3

- Проведена первая боевая транзакция.
- Не менее 30% заказов поступает через приложение.
- Выручка покрывает операционные расходы.

## Фаза 3. Полное покрытие МИФИ

Цель — охват всех точек питания МИФИ и его филиалов.

### Задачи

| #   | Задача                                                              | Слой           |
|-----|---------------------------------------------------------------------|----------------|
| 3.1 | Поддержка нескольких точек питания                                  | Архитектура    |
| 3.2 | Геолокация для выбора ближайшей точки                               | UX             |
| 3.3 | Аналитика продаж для администрации МИФИ                             | Бэк-офис       |
| 3.4 | Подключение филиалов в Обнинске, Сарове, Снежинске и других         | Развёртывание  |
| 3.5 | Автоматическая авторизация через СКУД                                | Интеграции     |
| 3.6 | Интеграция с расписанием для рекомендаций времени заказа            | Push           |
| 3.7 | Поддержка стипендиальных карт и программ льготного питания          | Платежи        |

### Критерий завершения

- Все 35 точек питания МИФИ и филиалов работают на МИФУД.
- Дневная активная аудитория не менее 1 000 пользователей.
- Не менее 30% заказов в столовых МИФИ поступает через приложение.

## Исключённые направления

Следующие задачи сознательно не включены в дорожную карту:

| Направление                          | Обоснование отказа                                               |
|--------------------------------------|------------------------------------------------------------------|
| **Выход за пределы МИФИ**            | Бренд и продукт спроектированы под конкретный вуз                |
| Доставка в общежития                 | Отдельная бизнес-модель с логистикой и упаковкой                 |
| Социальные функции вокруг блюд       | Избыточно для целевого сценария                                  |
| AI-рекомендации блюд                 | Недостаточный объём данных для качественного результата          |
| Чат с кухней в реальном времени      | Отсутствие операционной возможности на стороне столовой          |
| Собственная CRM-система              | Используются готовые решения, не наша зона компетенций           |
| Геймификация                         | Покрывается существующей мини-игрой ожидания                     |
| Приём криптовалют                    | Правовой статус не урегулирован в РФ                             |

## Технический долг

Перечень технических улучшений, не относящихся к функциональному развитию:

- Type hints во всех сервисных функциях.
- Документация API в формате OpenAPI.
- Retry-логика для webhook ЮKassa.
- Фоновые задачи на базе Celery или APScheduler вместо lazy-FSM.
- End-to-end тесты на ключевые сценарии.
- Локализация интерфейса на английский язык.
- Тёмная тема оформления.

## Принятые архитектурные решения

| Решение                            | Обоснование                                          | Условие пересмотра                      |
|------------------------------------|------------------------------------------------------|-----------------------------------------|
| Flask вместо FastAPI               | Серверный рендеринг с Jinja проще для команды        | Необходимость в JSON API                |
| HTMX вместо React или Vue          | Отсутствие отдельной JS-команды                      | Миграция на мобильное приложение        |
| SQLite на dev и PostgreSQL на prod | SQLite не требует настройки, PG нужен в production   | Не предвидится                          |
| In-memory pub/sub для SSE          | Один контейнер, внешний брокер избыточен             | Горизонтальное масштабирование          |
| Gunicorn в production              | Werkzeug не предназначен для боевой эксплуатации     | —                                       |
| Lazy-FSM вместо cron               | Отсутствие необходимости в планировщике задач        | Падение производительности на потоке    |
| Верификация webhook через re-fetch | ЮKassa не подписывает webhook-уведомления            | Появление подписей у ЮKassa             |
| Самохостинг Bootstrap и HTMX       | Нестабильность CDN в РФ и требования приватности     | —                                       |

---

## Заключение

MVP закрывает основной сценарий «студент оформил заказ и получил». Дальнейшее развитие направлено не на расширение функциональности, а на повышение надёжности, расширение охвата внутри МИФИ и углубление интеграций с инфраструктурой вуза.
