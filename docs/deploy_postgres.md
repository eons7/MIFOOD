# Подключение PostgreSQL — инструкция для коллеги (владельца Timeweb-аккаунта)

Приложение задеплоено на Timeweb Cloud App Platform с автодеплоем из GitHub.
Сейчас оно работает на SQLite внутри контейнера (данные теряются при каждом
редеплое). Нужно подключить PostgreSQL.

Код уже готов: при появлении переменной `DATABASE_URL` приложение автоматически
накатит миграции и переключится на Postgres.

## Шаги

### 1. Создать PostgreSQL в том же проекте, что и приложение

1. Боковое меню → **Базы данных** → **Создать**.
2. Тип: **PostgreSQL** (16, 17 или 18 — любая).
3. Регион: **тот же**, что у приложения. Иначе:
   - высокая латентность,
   - платный межрегиональный трафик.
4. Тариф: минимальный (1 CPU / 1 GB / 8 GB) — ~496 ₽/мес. Этого с запасом.
5. **Публичный IP**: можно не брать, если БД и приложение в одном проекте
   и видят друг друга по приватной сети. Сэкономит 180 ₽/мес.
6. **Физические бэкапы**: не нужны (учебный проект, есть seed). Сэкономит 120 ₽/мес.
7. Нажать **Заказать**, дождаться `running` (~2 минуты).

### 2. Получить строку подключения

После создания на странице БД будет блок «Подключение». Скопируй строку
вида:

```
postgresql://gen_user:LONGPASSWORD@host.timeweb.cloud:5432/default_db
```

Если в строке будут отдельные поля (host/port/user/password/dbname) —
собери из них URL по этому шаблону.

### 3. Добавить переменные окружения приложению

App Platform → твоё приложение `eons7-mifood-d798` → вкладка
**Переменные** (или «Environment»). Добавить **три** переменные:

| Имя           | Значение                                                          |
| ------------- | ----------------------------------------------------------------- |
| `DATABASE_URL` | Строка из пункта 2                                                |
| `FLASK_ENV`    | `production`                                                      |
| `SECRET_KEY`   | Длинная случайная строка (см. ниже как сгенерить)                 |

Сгенерировать SECRET_KEY можно любой командой:
```bash
python3 -c 'import secrets; print(secrets.token_hex(32))'
# или openssl rand -hex 32
```

Должна получиться строка вроде `8f3a2b9c4d5e6f...` (64 символа hex).
Записать её в `SECRET_KEY` — никому не показывать, в Git не коммитить.

### 4. Перезапустить приложение

После сохранения переменных нажать **Перезапустить** / **Перезапустить
контейнер**. Timeweb пересобирать не обязательно — переменные подхватятся
при рестарте.

### 5. Проверить работу

После рестарта в логах приложения должно быть:

```
[entrypoint] running flask db upgrade
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> ed82fa747c3f, ...
INFO  [alembic.runtime.migration] Running upgrade ed82fa747c3f -> a1b2c3, ...
INFO  [alembic.runtime.migration] Running upgrade a1b2c3 -> b2c3d4, ...
[entrypoint] starting gunicorn on 0.0.0.0:5000 workers=1 threads=8
[2026-... +0000] [...] [INFO] Listening at: http://0.0.0.0:5000
```

Если в логах ошибка `RuntimeError: DATABASE_URL не задан в production` —
переменная не подхватилась, проверить раздел Environment ещё раз.

Если ошибка `psycopg2.OperationalError: could not connect` — БД в другом
регионе/сети, или строка подключения с опечаткой.

### 6. Засеять демо-данные (один раз)

Открыть встроенную **консоль контейнера** в панели приложения и выполнить:

```bash
python -m app.seed
```

Это создаст:
- 4 категории (Сэндвичи, Первые блюда, Напитки, Добавки),
- ~20 позиций меню,
- 5 столов,
- 2 демо-юзера: `admin@mifi.ru` / `password` и `ivan@mifi.ru` / `password`.

(Пароли демо-юзеров можно поменять через интерфейс приложения позже,
либо удалить их и зарегистрировать своих.)

### 7. Готово

Открыть https://eons7-mifood-d798.twc1.net — должно работать на
Postgres, иметь HTTPS-куки и заголовки безопасности (CSP/HSTS/etc).

## Откат

Если что-то пошло не так — удали три переменные окружения
(`DATABASE_URL`, `FLASK_ENV`, `SECRET_KEY`) и перезапусти приложение.
Оно вернётся к SQLite-режиму как было.
